3. 실제 구현과 제안 설계 구분

기존 소스현재 기능캡스톤 적용 상태
pir_event.vPIR 동기화·rose/fall 이벤트연결·실물 미검증
ultrasonic_distance_meter.vHC-SR04 주기 측정, 거리·valid·timeout레벨 변환·샘플 갱신 펄스 검증 필요
ultrasonic_alarm.v거리 임계 경보, 16비트 거리 입력거리 10→16비트 확장·valid 의미 확인
status_registers.v2주소 일반 레지스터 예제AXI4-Lite 슬레이브 아님
capstone_controller.v온도·거리 기반 모터/LEDPIR 보안 Controller 아님
security_controller / security_regs보안 통합·이벤트 래치제안만 있음, 소스 없음

동작 순서(제안): PIR 상승 이벤트 → 초음파 엔진의 새 측정 결과 확인 → 정상 거리/타임아웃 분기 → 이벤트 저장 → LED·부저 경보. 기존 엔진은 주기 측정 방식으로 PIR 입력 시 즉시 TRIG를 발생시키지 않습니다. distance_valid 레벨을 1회 측정 완료 펄스로 해석하면 안 됩니다.

4. 제안 레지스터 맵 — 아직 구현되지 않음

Offset레지스터접근제안 의미
0x00CTRLRW[0] enable [1] arm [2] alarm_latch_enable
0x04STATUSRO[0] pir_motion [1] alarm [2] last_distance_valid [3] last_timeout [4] busy [5] armed
0x08DISTANCE_CMRO[9:0] 마지막 정상 거리, valid=0이면 사용 금지
0x0CEVENT_PENDINGRW1C[0] pir_rise [1] near_distance [2] echo_timeout
0x10THRESHOLD_CMRW[9:0] 경보 거리, 초기 제안 20 cm
0x14IRQ_ENABLERW[2:0] 이벤트별 인터럽트 허용

주소는 기존 IP의 실제 레지스터 주소가 아니라 32비트·4바이트 정렬 교육용 설계안입니다. EVENT_PENDING은 W1C(1을 쓰면 지움), 같은 클럭의 새 이벤트가 지움보다 우선합니다. AXI4-Lite 연결·주소 배정·C 드라이버는 아직 구현되지 않았습니다.

SoC 경로: A안은 기존 AMD AXI GPIO로 PIR/LED를 다루는 기초 실습, B안은 새 Controller·Register Bank를 표준 AXI4-Lite 슬레이브에 연결하는 확장 실습입니다. 기존 초음파 AXI 래퍼에는 WSTRB 누락·AW/W 동시 수락(P1 미해결) 문제가 있어 완전한 AXI IP로 승인하지 않았습니다.
