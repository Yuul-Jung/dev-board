# 아두이노 모듈 현황 (구조화·순서화)

<!-- nav -->[저장소 홈](../README.md) › [devices](README.md)

이 문서는 `tools/gen_status.py` 가 `data/module-status.csv`(모듈 72종)와 `data/chapter-status.csv`(교재 장)에서 만든 표입니다. 두 CSV 는 대시보드와 같은 자료입니다. 상태는 사람이 저장소 파일 유무를 대조해 적었고(근거 등급: 계산), 아래 §1 기준을 씁니다.

## 1. 판정 기준 (위에서 아래 순서로 따짐)

| 순서 | 상태 | 조건 |
|---|---|---|
| 1 | 완비 | 소자 문서 + 드라이버 C + 그 드라이버를 부르는 호스트 시험이 모두 있음 |
| 2 | 일부 | 드라이버나 RTL 은 있으나 호스트 시험이 없음(드라이버가 없고 RTL 만 있는 경우 포함) |
| 3 | 문서만 | 문서(또는 조사)만 있고 전용 드라이버·시험 없음 |
| 4 | 없음 | 문서도 드라이버도 없음 |

**「완비」도 한계가 있습니다**: 호스트 시험은 직접 만든 모의 장치를 상대로 한 것이라 데이터시트 해석이 틀리면 시험도 같이 틀립니다. 보드 실행과 Verilog 시뮬레이션은 하나도 없고, 판정 기준에도 들어 있지 않습니다(RTL 이 있는 모듈은 메모에 「RTL 시뮬레이션 전」으로 적음). 「완비」는 "저장소 안에서 할 수 있는 검증을 마쳤다"는 뜻이지 "동작이 확인됐다"는 뜻이 아닙니다.

## 6. 상태 판정을 바로잡은 이력

1. 처음 정리본은 「완비」를 30종으로 셌습니다. 드라이버 C 가 시험 파일에서 한 번이라도 쓰이는지 대조하자 `ds18b20.c`·`dht22.c`·`ultrasonic.c` 에 호스트 시험이 없었고(Verilog tb 만 있고 한 번도 돌리지 못함), HC-SR501·릴레이는 전용 드라이버·시험이 없었으며, microSD·ENC28J60 은 조사 문서가 있는데 「없음」으로 세었습니다 → 완비 25종으로 내림 (VERIFICATION.md 행 36).
2. 이어서 세 드라이버를 다시 쓰고 모의 장치 시험·변형 검사·사실표를 갖춰 「완비」로 올렸습니다 (행 37~39). 다시 쓰기 전 드라이버에는 결함이 12건 있었습니다(DS18B20 변환 대기 생략으로 +85 °C 를 읽음, CRC 미검사, 폴링 상한 없음 등).
3. L298(P02) 드라이버를 다시 읽다가 RTL 의 DUTY 레지스터가 16비트인데 기본 주기(100000 클럭)에서 66 % 넘는 듀티가 잘려 나가는 결함을 찾았습니다(모의 레지스터가 32비트로 저장해 기존 시험이 놓침). RTL 을 32비트로 넓히고 드라이버에 읽어 확인하는 단계를 넣었습니다 → 완비로 올림 (행 40). 「일부」 정의에서 「시뮬레이션·보드 확인 전」 조항을 뺐습니다: 앞서 DS18B20·DHT22·HC-SR04 를 같은 조건으로 완비로 올렸으므로 기준이 서로 어긋나 있었습니다.
4. MCP2515 가 S11 과 F02 로 두 번 들어 있습니다(중복). F02 메모에 표시했고 개수는 그대로 둡니다.
