## 4. 모듈 카탈로그 필드(문서 §12) 충족도 (계산)
- `data/devices.json` 은 **49건**(모듈 72종보다 적음)이고 필드는 소자마다 다름: `i2c_addr` 10건, `spi_modes` 7건, `vdd_v` 21건·`vcc_v` 17건, 근거 수준(`evidence`) 49건 전부.
- 문서의 `github_url`, `github_role`, `license`, `library_version_or_commit`, `vivado_version_tested`, `rtl_sim_status`, `board_test_status`, `schematic_url`, `vendor_url` 은 **저장소에 필드가 없음**. GitHub 쪽은 [REFERENCES.md](REFERENCES.md) 대장으로 따로 시작(라이선스·commit 은 원문 미열람이라 대부분 「미기록」).
- 증거 단계(후보 → 자료검토 → 전기 호환 → RTL 시뮬레이션 → Vivado 합성 → 보드 → 재사용): 저장소의 최고 단계는 **자료검토 + 호스트 모의 시험**입니다. RTL 시뮬레이션·합성·보드·MicroBlaze V 실행은 **0건**(시뮬레이터·보드가 없음, 확인). 문서 §10 의 차시별 완료 기준(보드에서 확인 등)은 **하나도 충족되지 않음**.

## 6. 결정이 필요한 것 (미결)
1. **ENC28J60·W5500 의 「AMD 중복」 판단**: AMD 의 이더넷 IP(AXI Ethernet Lite)는 PHY 가 필요한데, Basys3 에 이더넷 PHY 가 있는지는 확인하지 못했습니다(일반 지식으로는 없음, **미확인**). PHY 가 없다면 유선 이더넷은 SPI 모듈(W5500 등)이 실제 경로이므로 ENC28J60 제외가 맞는지 재검토가 필요합니다. W5500 은 이미 「완비」입니다.
2. 프로젝트 문서에 P06 추가와 §11 의 5·6 개정을 반영할지(제안은 위에 적음).
3. G03~G06 을 일반 GPIO 입력 문서 하나로 묶을지.
4. 사용자 확정 회로도(L298 모듈, HC-06, HM-10, I²C LCD 백팩)는 아직 받지 못함(TODO.md).
