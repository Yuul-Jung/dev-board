## NEO-6M (u-blox NEO-6 GPS) — D1
| 항목 | 값 |
|---|---|
| 전원 | NEO-6M/6Q: 2.7 / 3.0 typ / 3.6 V (NEO-6G는 1.8 V대) |
| UART | 기본 9600 baud, 8N1. NMEA와 UBX 포트이나 시작 시 NMEA만 활성 |
| 부팅 시 선택 가능 보레이트 | 4800, 9600, 38400, 57600 (그 외 전체 목록은 문서에 없음) |
| 기본 NMEA | GGA, GLL, GSA, GSV, RMC, VTG, TXT |
| 갱신율 | 최대 5 Hz (기본 1 Hz는 문서에 명시 없음) |
| 첫 위치 확보 | 콜드 32 s(6M), 핫 1 s 미만, 보조 시 3 s 미만(6M) |
| 정확도 | 수평 2.5 m(자율), 2.0 m(SBAS) |
| 1PPS | TIMEPULSE 기본 1 pulse/s, 상승 에지 동기, 100 ms 폭 (0.1 Hz~1 kHz 설정 가능) |
| 3.3 V IO | 문서에 명시 없음. 입력 하이 0.7×VCC, 출력 하이 VCC-0.4 V |

SoC (설계안): UART Lite 9600, RX 만 필요(수신 전용). 1PPS 는 GPIO 인터럽트 또는 타이머 캡처 후보. 모듈 보드는 레귤레이터/레벨이 모듈마다 달라 보드 사양 확인 필요(미확인).
소프트웨어: NMEA 줄 조립·체크섬·RMC 파서는 `sw/nmea.c` (NavSpark 문서 기준, 미확인 항목은 README 참조).

## HC-05 (Bluetooth SPP 모듈) — D3 (2차 자료)
| 항목 | 값 |
|---|---|
| 규격 | Bluetooth V2.0+EDR, SPP |
| 전원·IO | "1.8V Operation", "1.8 to 3.6V I/O" — 모듈 보드 전원 범위는 문서에 불분명 |
| 기본 보레이트 | 38400, 8N1 |
| AT 명령 | AT(OK) · AT+NAME · AT+PSWD(기본 1234) · AT+UART=baud,stop,parity · AT+ROLE(0 슬레이브, 1 마스터, 2 슬레이브 루프) |
| AT 모드 진입 | PIO11을 전원 투입 전에 High로 (이 자료 기준; KEY 핀 표기는 문서에 없음) |
| 핀 PIN | 자료 내 상충: 자동 페어링 "0000" vs AT+PSWD 기본 1234 |

AT 모드 보레이트가 38400 이라고 단정할 수 없어 미확인입니다. 1차(제조사) 데이터시트가 아니므로 D3.
SoC (설계안): UART Lite 38400. 모듈 전원/레벨이 3.3 V 인지 확인 전에는 TXD 를 FPGA 로 직결하지 않기.

## HC-06 (Bluetooth 클래식 SPP 슬레이브 모듈) — D3 (2차 자료, 같은 저자의 글 2건)
출처: Martyn Currey 의 HC-06 글 두 편([?p=12932](https://martyncurrey.com/?p=12932), [?p=1571](https://martyncurrey.com/?p=1571)), 웹 가져오기 요약 경유. **같은 저자라 서로 독립적이지 않고**, 일부는 저자 본인의 실험입니다. 제조사 데이터시트는 열지 못했습니다.
| 항목 | 값 | 근거 |
|---|---|---|
| AT 명령 형식 | 대문자, **줄 끝(CR/LF) 없음**, 응답도 줄 끝 없음 | 저자(D3) |
| 모드 | 전원을 넣으면 AT 모드, 연결되면 전송 모드(연결이 끊길 때까지 AT 를 받지 않음) | 저자(D3) |
| 기본 | 보레이트 9600(코드 4), PIN 1234 | 저자(D3) |
| `AT` | → `OK` | 저자 |
| `AT+VERSION` | → `OKlinvorV1.8` (모듈에 따라 `hc01.comV2.0`) | 저자 |
| `AT+NAMEx` | → `OKsetname` (이름 최대 20자, 새 이름은 전원을 다시 넣어야 보일 수 있음) | 저자 |
| `AT+PINxxxx` | → `OKsetPIN` (숫자 4자리) | 저자 |
| `AT+BAUDx` | → `OK<보레이트>`, x = 1~9, A, B, C = 1200 2400 4800 9600 19200 38400 57600 115200 230400 460800 921600 1382400 | 저자 |
| `AT+PN` `AT+PE` `AT+PO` | 패리티 없음/짝수/홀수 (응답 미상) | 저자 |
| `AT+LED0/1`, `AT+ROLE=S/M` | `hc01.comV2.0` 펌웨어만 (응답 미상) | 저자 |
| 전원·레벨 | 보드 VCC 3.6~6 V(온보드 3.3 V 레귤레이터 전제, 안쪽 모듈 EGBT-046S 정격은 3.1~4.2 V), RX 는 3.3 V 신호만(5 V 비허용), TX 는 3.3 V 라 FPGA 에 직결 가능 | 저자 견해 + 저자의 보드 관찰(D3) |
| 보드 핀 | HC-06 보드는 4핀(VCC GND TXD RXD)뿐이고 EN·STATE 핀과 버튼이 없음(HC-05 보드는 있음). 판매사 슬라이드는 "5 V 전원, 3 V 레귤레이터, TTL 출력, 보레이트 1200~1382400(기본 9600)"이라 적어 **보레이트 범위 양 끝과 기본값은 저자와 독립으로 일치** | 저자 + [판매사 슬라이드](https://www.slideshare.net/slideshow/bluetooth-module-hc06/53593901)(D3, 요약 경유) |

SoC (설계안): UART Lite 9600. **Basys3 Pmod 의 3.3 V 로는 모듈 보드(3.6~6 V)를 켤 수 없음** → 외부 5 V 와 GND 공통이 필요하고, 모듈 TX→FPGA RX 는 3.3 V 라는 저자 견해를 믿고 직결하기 전에 보드의 실제 레벨을 확인해야 합니다(미확인). UART Lite 의 보레이트는 합성 때 정해지므로 모듈의 보레이트를 바꾸면 FPGA 설계도 다시 합성해야 합니다(PG142, 확인).
책(28장)이 쓰는 모듈입니다. HC-05 와 달리 AT 명령에 줄 끝이 없어 [`hc05_send`](sw/hc05.c) 를 쓸 수 없고, 응답의 끝을 **무음 구간**으로 판단하는 [`btmod`](sw/btmod.h) 를 따로 만들었습니다.
미확인: 제조사 데이터시트, 펌웨어별 차이(한 독자가 일부 모듈에서 `AT+BAUD` 가 안 되고 `AT+UART` 가 된다고 보고 — 이 코드는 `AT+UART` 를 지원하지 않음), 명령 사이 간격 요구, 보레이트 변경 직후 응답이 새·옛 보레이트 중 무엇으로 오는지, 응답까지 걸리는 시간.

## HM-10 계열 (CC2541 BLE UART 모듈, 저전력 블루투스) — D1 (요약 경유, 문서 안 불일치 많음)
출처: A = Itead 사본 DS_IM130614001 ([PDF](https://shop-archive.boxtec.ch/pub/iteadstudio/DS_IM130614001_Serial_Port_BLE_Module_Master_Slave_HM-10.pdf)), B = DSD TECH "HM-10 DataSheet" Last Version V545(2017-01, Cornell 강의 사본). 둘 다 웹 가져오기 요약 경유라 PDF 원문을 직접 읽은 것은 아닙니다("D1(요약 경유)"). 펌웨어 V5xx 만 다루며 V6xx·V7xx 는 열지 못했습니다.
| 항목 | 값 | 근거 |
|---|---|---|
| AT 명령 형식 | 대문자, 줄 끝 없음. 응답은 `OK` 또는 `OK+<태그>[:<값>]`, 줄 끝 없음 | A·B |
| 모드 | 연결되지 않았을 때만 UART 의 AT 명령을 받음(전송 버전) | A·B |
| 기본 | 이름 `HMSoft`(최대 12자), 9600 8N1, PIN `000000`, 슬레이브(주변장치) | A·B |
| `AT+BAUDn` | 0=9600 1=19200 2=38400 3=57600 4=115200 (A·B 일치), 5=4800 6=2400 7=1200 8=230400 (B 만) | A·B |
| 1200 | "다음 전원부터 PIO0 를 누르기 전에는 AT 를 받지 않음" 경고 → 이 코드는 1200 을 보내지 않음 | B |
| 조회 | `AT+NAME?` `ADDR?` `VERS?` `BAUD?` `ROLE?` `MODE?` `PASS?` `TYPE?` `POWE?` `NOTI?` | A·B |
| 설정 | `AT+ROLE` 0=주변장치 1=중앙 · `AT+MODE` 0=전송 1=PIO 수집 2=원격 제어 · `AT+PASS` 000000~999999 · `AT+TYPE` 0~3(3 은 V524+, V515 미만은 쓰지 말 것) · `AT+POWE` 0~3 · `AT+NOTI` 0/1 | A·B |
| 기타 | `AT+RESET`→`OK+RESET` · `AT+RENEW`→`OK+RENEW` · `AT+SLEEP`→`OK+SLEEP` · `AT+START`→`OK+START` · 알림을 켜면 연결·끊김 때 `OK+CONN`/`OK+LOST` | A·B |
| BLE | 서비스 0xFFE0, 특성 0xFFE1. 모드 1·2 에서 UART 로 보내는 데이터는 한 번에 "20바이트 미만" | A·B |
| 전원 | **칩 모듈**: 3.3 V (B: +2.5~3.3 V, 50 mA; Components101 은 2.0~3.6 V, 최대 3.9 V라고 해 문서끼리 다름). **아두이노용 브레이크아웃 보드**: 온보드 3.3 V 레귤레이터가 있고 VCC 핀 정격이 3.6~6 V ([Martyn Currey](https://www.martyncurrey.com/?p=4463), D3). 칩 모듈의 핀은 3.3 V 전용이며 5 V 비허용 | A·B + 저자(D3) |
| 보드 핀 | 브레이크아웃 6핀: STATE(연결 전 Low, 연결되면 High) RXD TXD GND VCC BRK(연결 중 Low 를 주면 연결 끊김). LED 는 연결 대기 중 깜박이고 연결되면 켜짐 | 저자(D3) |

**문서 안의 불일치(그대로 둠, 코드는 양쪽을 모두 받도록 만듦)**: 응답 접두가 `OK+Get:`/`OK+Set:` 인데 이름 설정은 `OK+Set<값>`(표) 대 `OK+SetName:<값>`(예), PASS 조회는 `OK+Get:`(표) 대 `OK+PIN:`(예), `AT+NAME` 조회의 물음표가 전각(？)으로 인쇄됨(조판 오류로 보고 ASCII `?`), `AT+UUID` 대 `AT+CHAR`, `AT+PWRM` 의 의미 뒤바뀜. [`hm10_parse`](sw/hm10.c) 는 첫 `:` 에서 태그와 값을 나누고, 설정 성공은 "태그가 `Set` 으로 시작"으로 판정합니다.
SoC (설계안): UART Lite 9600(기본). **어느 보드냐에 따라 전원이 다릅니다**: 칩 모듈 단품이면 Pmod 3.3 V 로 켤 수 있지만, 레귤레이터가 있는 브레이크아웃(아두이노용으로 흔한 형태)은 VCC 정격이 3.6~6 V 라 3.3 V 로는 레귤레이터 전압 강하 때문에 못 켤 수 있습니다(저자 표기 기준, 미확인). 이전 문서의 "3.3 V 로 켤 수 있어 Pmod 와 맞다"는 이 구분 없이 쓴 것이라 정정합니다. I/O 는 3.3 V 전용이라 FPGA(3.3 V)에 직결해도 레벨은 맞습니다. 책(29장)은 ESP32-S3 의 BLE 를 쓰므로, 이 모듈은 "Arduino 주변 모듈로서의 BLE UART 브리지"를 다룰 뿐 ESP32-S3 의 BLE 스택은 아닙니다.
미확인: 제조사(JNHuaMao) 최신 데이터시트, V6xx·V7xx 펌웨어, 복제 모듈의 동작, 응답까지 걸리는 시간, 전원 투입 후 AT 를 받기까지의 대기, 응답 조각 사이 간격.

## MAX485 (RS-485 트랜시버) — D1
| 항목 | 값 |
|---|---|
| 전원 | 5 V ±5% (4.75~5.25 V) |
| 속도·방식 | 최대 2.5 Mbps, 반이중, 버스 32개까지 |
| 핀 | RO, DI, DE, RE, A, B |
| 수신 (RE=0, DE=0) | A-B ≥ +0.2 V → RO=1, A-B ≤ -0.2 V → RO=0, 입력 개방 시 RO=1 |
| 비활성 (RE=1, DE=0) | 출력 고임피던스 |
| 수신 임계 | ±0.2 V, 공통 모드 -7~+12 V, 히스테리시스 70 mV |
| 논리 입력 (DE, DI, RE) | VIH 최소 2.0 V, VIL 최대 0.8 V |
| 구동 출력 | 차동 ≥1.5 V (27 Ω), 최대 무부하 5 V, 단락 전류 35~250 mA |
| 송신 진리표 | 추출 표가 깨져 출력 레벨 대응은 미확인 |

SoC (설계안): UART Lite TX → DI, RO → RX, DE 와 RE 를 묶어 GPIO 1비트로 방향 제어(송신 직전 High, 마지막 바이트 전송 완료 후 Low; 완료 시점은 UART Lite 상태 비트가 필요하며 미확인).
FPGA(3.3 V) 출력은 VIH 2.0 V 이상이라 DI/DE/RE 직결 가능(계산). RO 의 출력 전압은 열어본 부분에 없어, 5 V 전원에서 3.3 V 입력으로 넣을 수 있는지 미확인 — 확인 전에는 분압 또는 레벨 변환.
