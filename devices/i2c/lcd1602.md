# 문자 LCD: HD44780 (16×2, 20×4) 과 PCF8574 I2C 백팩

<!-- nav -->[저장소 홈](../../README.md) › [devices](../README.md) › [i2c](README.md)

교재 15·19장(텍스트 LCD, I2C LCD)에 해당합니다. 드라이버: [`sw/hd44780.h`](sw/hd44780.h), [`sw/hd44780.c`](sw/hd44780.c), PCF8574 접착 코드 [`sw/hd44780_pcf8574.h`](sw/hd44780_pcf8574.h). 시험: [`tb/test_hd44780.c`](tb/test_hd44780.c). 사실표: [`ref/hd44780_facts.txt`](ref/hd44780_facts.txt). PCF8574 자체는 [io-expander.md](io-expander.md).

**근거**: Hitachi HD44780U 데이터시트(soldered.com 사본)를 웹 가져오기가 요약한 본문(D1, 요약 경유 — PDF 원문은 직접 열지 못함), 명령 코드·실행 시간·DDRAM 범위·CGRAM 은 Wikipedia(D3)와도 일치. 요약은 표 머리글이 깨져 전압 열을 표 순서로 추정했다고 밝혔고 쪽수는 근사값입니다. 초기화 대기·버스 타이밍은 두 번째 출처가 없습니다.

## 확인된 사실
| 항목 | 값 |
|---|---|
| 명령 | 지우기 01h · 홈 02h · 입력 모드 04h \| I/D(02h) S(01h) · 표시 08h \| D(04h) C(02h) B(01h) · 시프트 10h \| S/C(08h) R/L(04h) · 기능 설정 20h \| DL(10h) N(08h) F(04h) · CGRAM 주소 40h \| A5..0 · DDRAM 주소 80h \| A6..0 (모두 RS=0, R/W=0) |
| 실행 시간 (fOSC 270 kHz) | 지우기·홈 1.52 ms, 나머지 37 µs. fOSC 는 190~350 kHz 로 흩어지므로 최악(190 kHz)은 약 2.16 ms / 52.6 µs (계산) |
| 4비트 초기화 (Figure 24) | Vcc 가 4.5 V 에 도달한 뒤 >15 ms (2.7 V 에 도달한 뒤는 >40 ms) → 0011 → >4.1 ms → 0011 → >100 µs → 0011 → 0010(4비트 전환) → 기능 설정 → 표시 끔 → 지우기 → 입력 모드. 그 뒤 행 수·글꼴은 바꿀 수 없음 |
| 버스 타이밍 | 2.7~4.5 V 쪽 최악: E 주기 ≥ 1000 ns, E 하이 ≥ 450 ns, 주소 셋업 60 ns, 데이터 셋업 195 ns, 데이터 홀드 10 ns, 주소 홀드 20 ns. 4.5~5.5 V 쪽은 500/230/40/80/10/10 ns |
| DDRAM | 2행: 첫 행 00~27H, 둘째 행 40~67H. 1행: 00~4FH |
| CGRAM | 64바이트. 5×8 글자 8개(5×10 은 4개) |

## 드라이버
- 포트 한 바이트를 쓰는 함수 `wr(ctx, byte)` 와 마이크로초 지연 `delay(ctx, us)` 만 요구합니다. I2C 백팩이든 GPIO 직결이든 같은 코드입니다. 핀 배치는 비트 위치 구조체(`hd44780_pins_t`)로 줍니다(RW·백라이트는 미연결 가능).
- **바쁨 플래그를 읽지 않고 고정 대기**를 씁니다(RW 는 항상 0): 일반 명령 60 µs(최악 52.6 µs 위), 지우기·홈 2.5 ms(최악 2.16 ms 위), 전원 대기 50 ms(2.7 V 기준 >40 ms 위). E 펄스는 데이터 확정 → E 상승 → E 하강을 1 µs 단위 지연으로 이어서 셋업·폭·주기 요구를 모두 넘깁니다(지연 분해능 1 µs 가정).
- 기능: `hd44780_init`, `clear`, `home`, `set_cursor`, `putc`, `print`(행 끝에서 멈추고 `HD44780_ERR_RANGE`), `print_int`, `display`/`cursor`/`blink`, `backlight`, `shift_display`, `create_char`(슬롯 0..7, 쓴 뒤 DDRAM 주소를 커서 위치로 되돌림). 행 끝을 넘겨 쓰면 보이지 않는 RAM 에 쓰게 되므로 막았습니다.
- 20×4 의 3·4 행 시작 주소는 데이터시트에 없는 모듈 관례(행 3 = 열 수, 행 4 = 0x40 + 열 수 → 20열이면 0x14, 0x54)를 기본값으로 쓰며 `row_addr` 로 바꿀 수 있습니다(설계안).

## PCF8574 백팩
- 접착 코드는 `pcf8574_write` 로 포트 바이트를 씁니다. 백팩의 핀 배치는 **모듈 관례**(P0 RS, P1 RW, P2 E, P3 백라이트, P4~P7 = D4~D7)를 기본값 `HD44780_PINS_PCF8574_COMMON` 으로 두었지만 데이터시트 근거가 없고 모듈마다 다릅니다 → 사용하는 모듈 회로를 확인하세요(설계안, 미확인).
- 글자 하나(=니블 2개)에 포트 쓰기가 6번이라 I2C 전송이 6번 일어납니다. 100 kHz 에서 한 번에 약 0.2 ms 정도(주소+데이터 2바이트, 계산)이므로 한 글자가 1 ms 남짓입니다.
- **백팩 모듈 대조(이번 추가, D3)**: [SunFounder I2C LCD1602](https://docs.sunfounder.com/projects/thales-kit/en/latest/components/i2c_lcd1602.html) — PCF8574 사용, 기본 주소 0x27(경우에 따라 0x3F), A0·A1·A2 패드는 기본 1이고 패드를 납땜으로 이으면 0, **VCC 는 5 V**, SDA/SCL 은 풀업을 통해 VCC 에 연결해야 한다고만 적혀 있어 풀업이 모듈에 있는지는 알 수 없음, 대비 조절용 파란 가변저항과 백라이트 점퍼가 있음, 회로도 없음. 주소는 PCF8574 의 0x20+A2A1A0(=111 → 0x27)·PCF8574A 의 0x38+A2A1A0(→ 0x3F)와 산수가 맞음(계산).
- **핀 배치는 근거가 갈림**: 오픈소스 코드 한 건([kingkevin/stm32f1](https://git.cuvoodoo.info/kingkevin/stm32f1/commit/a751b95352b98bd3e5093149663c2a3a256a942d))은 이 문서의 기본값과 같은 P0 RS · P1 RW · P2 E · P3 LED · P4~P7 D4~D7 이라고 주석에 적었지만, Arduino 포럼 글 두 건은 서로 다르게(2013: P1 = E, RW 는 GND / 2019: P2 = E) 적었습니다. 즉 **P0=RS, P2=E 는 흔하지만 모든 백팩의 사실은 아닙니다.** 회로도가 확정된 실제 백팩으로 `hd44780_pins_t` 를 정해야 합니다.
- **전원 전압 불일치 위험**: 위 모듈은 VCC 5 V 인데 Basys3 Pmod 는 3.3 V 뿐입니다. 5 V 로 켜면서 풀업까지 5 V 에 걸려 있다면 SDA/SCL 이 FPGA(3.3 V) 입력에 5 V 를 줍니다 — 아래 미확인 항목(풀업 전원)이 이 때문에 안전과 직결됩니다.
- 주의(미확인): 백팩은 보통 5 V 전원에 I2C 풀업이 그 전원에 붙어 있는 경우가 많다고 알려져 있으나 이번에 모듈 자료를 확인하지 않았습니다. 3.3 V 신호만 내는 FPGA 에 붙이기 전에 SDA/SCL 풀업 전원과 HD44780 의 입력 하이 레벨 최소값(요약에 없음)을 확인하세요. 3.3 V 로 구동하는 모듈은 오실레이터가 느려진다는 자료가 있으나 값은 확인하지 못했습니다(대기 상수에 여유를 둠).
- `pcf8574_init` 은 모든 비트를 1 로 쓰므로 순간적으로 E·RS·RW 도 High 가 됩니다. 전원 대기 중이라 영향이 없을 것으로 보이나 확인하지 않았습니다.

## 시험
- 모델은 데이터시트 요약의 규칙을 구현해 어기면 기록합니다: 전원 후 첫 E 하강 ≥ 40 ms, 0011 세 번 사이 간격, 4비트 전환, 높은 니블 다음 낮은 니블, 명령 실행 중(바쁨) E 하강 금지(지우기·홈 2.16 ms, 나머지 52.6 µs), E 폭·주기·데이터 셋업·홀드(3 V 쪽 최악), E 가 높은 동안 데이터 변경 금지, RW=0, DDRAM 주소 유효 범위, CGRAM 쓰기. 화면 내용은 모듈 관례의 행 시작 주소로 읽습니다.
- 확인: 16×2·20×4·16×4·1행·40열 초기화와 출력, 다른 핀 배선(역순 포함), 사용자 글자와 DDRAM 복귀, 행 끝 처리, 표시 제어, 백라이트, 인자 오류, 쓰기 함수 실패 전파(어느 지점에서 실패해도 같은 오류), 버스 비용 0 과 25 µs 두 경우. 음성 대조로 대기를 절반으로 줄이면 모델이 위반을 잡는 것도 확인.
- ASan/UBSan 통과. 틀리게 만든 사본 75개가 모두 실패로 잡힘(명령 코드·핀 매핑·대기·펄스·니블 순서·행 주소 등).
- **한계**: 글자 ROM 표(A00/A02)와 ASCII 의 차이, 5×10 글꼴, 실제 모듈의 대비·전원, 보드에서의 실행은 확인하지 못했습니다. 모델은 내가 읽은 요약대로 내가 만든 것이라 요약이 틀리면 같이 틀립니다.
