# SSD1306 OLED (I2C) 드라이버

<!-- nav -->[저장소 홈](../../README.md) › [devices](../README.md) › [i2c](README.md)

128×64 단색 OLED. 드라이버: [`sw/ssd1306.h`](sw/ssd1306.h), [`sw/ssd1306.c`](sw/ssd1306.c), 시험: [`tb/test_ssd1306.c`](tb/test_ssd1306.c)(전송 바이트), [`tb/test_oled_gfx.c`](tb/test_oled_gfx.c)(그리기), 사실표: [`ref/ssd1306_facts.txt`](ref/ssd1306_facts.txt). SPI 연결 정보는 [../spi/display.md](../spi/display.md). 책 23장(도형·이미지)에 대응해 선·원·삼각형·비트맵·5×7 글꼴을 추가했다.

## 근거 수준
이번에 **데이터시트 사본의 요약**을 열었다(store.comet.bg 의 PDF, 웹 가져오기 요약 경유 → D1(요약 경유)). 요약은 이 PDF 가 **SSD1306B Rev 1.1** 이며 원본 SSD1306 과 다를 수 있다고 경고했다. 명령 코드 값은 Microchip ASF 헤더(33개 매크로, D3)와 독립적으로 대조했고 모두 일치한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 7비트 주소 | 0x3C (SA0=0), 0x3D (SA0=1); D/C# 핀이 SA0 | **D1(요약 경유)** |
| 제어 바이트 | Co=비트 7, D/C#=비트 6, 나머지 0. 명령 0x00, 데이터 0x40 (Co=0 이면 이후 바이트 전부 같은 종류) | D1(요약 경유) |
| 명령 코드 | 0x20 0x21 0x22 0x40 0x81 0x8D 0xA0/A1 0xA4 0xA6/A7 0xA8 0xAE/AF 0xC0/C8 0xD3 0xD5 0xD9 0xDA 0xDB | D1(요약 경유) + ASF(D3), 0x40 은 ASF 만 |
| 인자·리셋 값 | 메모리 모드 리셋 = 페이지(10b), 가로 = 00b / 열 0~127·페이지 0~7 / 대비 리셋 7F / MUX 리셋 3F(64) / 오프셋 리셋 0 / 클럭 리셋 0x80 / COM 핀 리셋 0x12 / 프리차지 리셋 2·2 DCLK / VCOMH 리셋 0.77×VCC | D1(요약 경유) |
| COM 핀(0xDA 인자) | **0x02 = 순차, 0x12 = 번갈아(리셋 값)**. A[5] 는 좌우 리맵 | D1(요약 경유) — 이전의 "미확인"을 해소. 어느 값이 **내 모듈**에 맞는지는 여전히 모듈마다 다름 |
| 충전 펌프 | 인자 0x14 = 켬(7.5 V), 순서 0x8D → 0x14 → 0xAF | D1(요약 경유) |
| 최대 SCL 클럭 | 요약에 없음(Table 12-6 미포함) | **미확인** |
| 모듈 승압 회로 유무·방향(위아래/좌우) | 모듈마다 다름 | **미확인** |

초기화 20바이트 중 0x40(시작 줄)만 데이터시트 요약에서 확인하지 못했고(ASF 이름 `SET_DISPLAY_START_LINE(line)` = 0x40|line), 나머지 인자는 리셋 값과 같거나 데이터시트 값과 일치한다. 0xD9·0xDB 는 쓰지 않아 리셋 값이 적용된다(일부 모듈 예제가 쓰는 밝은 값과는 다를 수 있음 — 화면이 어두우면 의심).

## 동작
- 초기화: 표시 끔 → 클럭 → 멀티플렉스 63 → 오프셋 0 → 시작줄 0 → 차지 펌프 → 가로 주소 모드 → 리맵 → COM 스캔 → COM 핀 → 대비 → 표시 켬. 트랜잭션은 명령 경계(7·7·6바이트)로 나눔. `flip=1` 이면 A0/C0(리셋 값), `flip=0` 이면 A1/C8.
- 프레임버퍼 1024 바이트(`fb[page*128+x]`, 비트0 = 페이지 맨 위). `oled_flush` 는 창 0..127 × 0..7 설정 후 페이지당 한 트랜잭션(제어 0x40 + 128바이트).
- `oled_invert` 는 0xA7/0xA6 만 보내고 프레임버퍼는 그대로.

## 그리기 (책 23장 대응)
| 함수 | 내용 |
|---|---|
| `oled_pixel`, `oled_hline`, `oled_rect` | 점·가로줄·사각형(외곽선/채움). 범위 밖은 잘라냄. 이번에 정수 넘침·긴 반복이 없도록 64비트 범위 계산으로 고침(VERIFICATION 행 33) |
| `oled_line` | Bresenham, 양끝 포함, 어떤 기울기·방향도 가능 |
| `oled_circle`, `oled_fill_circle` | 중점 원 외곽선 / 채움(dx²+dy² ≤ r²+r, 외곽선 포함). r=0 은 점 |
| `oled_triangle` | 외곽선(세 선) 또는 채움(행마다 세 변 픽셀의 최소~최대 x) |
| `oled_bitmap` | 행 우선, 한 행 (w+7)/8 바이트, 바이트의 **최상위 비트가 왼쪽**. 1 비트는 fg, 0 비트는 bg(`OLED_TRANSPARENT` 면 그대로). Adafruit `drawBitmap` 과 같은 형식으로 알려졌으나 **책이 쓰는 형식은 책 본문을 못 봐서 미확인**. XBM(최하위 비트가 왼쪽)은 그대로 못 쓴다 |
| `oled_print` | 5×7 글꼴, 칸 6×8(오른쪽 한 열·아래 한 행은 간격), 배율 1~8, `\n` 줄바꿈, ASCII 0x20~0x7E(그 밖은 `?`), 불투명/투명 배경 |
| `oled_text` | 기존 3×5 숫자 글꼴(센서 값 표시용), 변경 없음(배율만 8 로 제한) |
- 좌표 절댓값이 `OLED_COORD_LIM`(4096)을 넘는 선·원·삼각형·비트맵·글자는 그리지 않는다(반복 횟수 한도). 한글·확장 문자는 없다.
- **5×7 글꼴 표는 출처 문서가 없다.** 기억에 의존한 고전적인 5×7 글꼴 표를 입력하고(따옴표·물결표만 직접 그림) 전체 글자를 ASCII 아트로 찍어 눈으로 확인했다. 시험은 7행 이내·공백만 비어 있음·모든 글자가 서로 다름·몇 글자(A E 0 ? a p ~) 모양을 본다. 저작권/라이선스 출처를 따질 문서가 없으므로 공개 전에 필요하면 직접 만든 글꼴로 바꾸는 것이 안전하다(미확인).

## 시험 결과와 한계
- `test_ssd1306.c`: 가짜 `axi_iic_write` 로 전송 바이트열 기록 — 초기화 순서 20바이트(이번에 헤더 상수로 바꿨고 바이트열 동일), 창 설정, 페이지 8개×129바이트, 표시 켬, 오류 전파.
- `test_oled_gfx.c`(성질 기반, 드라이버 코드를 복사한 기대값 없음): 선은 주축마다 정확히 한 점이고 이상 직선에서 0.5칸 이내(6천 개 무작위+팔방+화면 밖), 원은 8방향 대칭·행/열 빈틈 없음·반지름 편차 최대 0.485칸(r ≤ 31 측정), 채운 원은 모든 r·중심에서 dx²+dy² ≤ r²+r 와 정확히 일치, 삼각형은 기하 거리/내부 판정(경계에서 1칸 이상 안쪽은 반드시 칠함, 칠한 점은 경계에서 0.5칸 이내, 외곽선 ⊂ 채움), 모든 도형·비트맵·글자가 **평행 이동 불변**(화면 밖으로 잘려도 겹치는 부분이 같음), 극단 값(INT_MIN/MAX) 무작위 호출 6만 회에서 ASan/UBSan 통과.
- 소스 변형 검사 결과는 [VERIFICATION.md](../VERIFICATION.md) 행 34.
- **이 시험은 프레임버퍼까지만 봅니다.** 실제 화면의 방향, 대비, 충전 펌프, 모듈 배선은 보드에서 확인해야 합니다. 화면이 비거나 줄이 섞이면: 차지 펌프(모듈에 승압 회로가 없으면 외부 전원 필요), COM 핀 값(0x02↔0x12), 주소(0x3C↔0x3D)를 순서대로 의심.
- 아직 없는 것: 하드웨어 스크롤(0x26/0x27/0x29/0x2A/0x2E/0x2F — 코드 값만 ASF 로 확인, 인자 미확인), 일부 영역만 전송하는 갱신, 128×32 모듈(Pmod OLED, SPI)용 초기화, 부분 갱신으로 I2C 전송량 줄이기.
