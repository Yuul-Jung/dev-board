# ADS1115 (16비트 I2C ADC)

<!-- nav -->[저장소 홈](../../README.md) › [devices](../README.md) › [i2c](README.md)

드라이버: [`sw/ads1115.h`](sw/ads1115.h), [`sw/ads1115.c`](sw/ads1115.c). 시험: [`tb/test_ads1115.c`](tb/test_ads1115.c). 근거는 TI SBAS444 데이터시트 웹 문서(D1; 영문판 Config 절, 일문판 I2C·사양 절). PDF 를 직접 열지는 못했습니다.

## 확인한 사양
| 항목 | 값 |
|---|---|
| 7비트 주소 | ADDR→GND 0x48, VDD 0x49, SDA 0x4A, SCL 0x4B (SDA 로 정할 때 SCL 하강 후 SDA 를 100 ns 이상 Low 유지) |
| 포인터 | 00 변환값, 01 Config(리셋 8583h), 10 Lo_thresh(8000h), 11 Hi_thresh(7FFFh) |
| 바이트 순서 | 쓰기·읽기 모두 MSB 먼저 |
| Config | OS[15] MUX[14:12] PGA[11:9] MODE[8] DR[7:5] COMP_MODE[4] COMP_POL[3] COMP_LAT[2] COMP_QUE[1:0] |
| MUX | 000 AIN0-1, 001 AIN0-3, 010 AIN1-3, 011 AIN2-3, 100~111 AIN0~3 대 GND |
| PGA / LSB | ±6.144 V 187.5 µV, ±4.096 V 125 µV, ±2.048 V 62.5 µV(리셋), ±1.024 V 31.25 µV, ±0.512 V 15.625 µV, ±0.256 V 7.8125 µV |
| 데이터 속도 | 8, 16, 32, 64, 128(리셋), 250, 475, 860 SPS. 변환 시간 = 1/DR |
| 출력 | 16비트 2의 보수, +FS = 7FFFh, −FS = 8000h, 범위를 넘으면 포화 |
| 단발 | MODE=1 에서 OS=1 쓰기로 시작. 읽을 때 OS=0 이면 변환 중, 1 이면 끝 |
| 전원·입력 | VDD 2.0~5.5 V. 아날로그 입력은 **VDD + 0.3 V 초과 금지** |
| SCL | 400 kHz, 고속 모드 3.4 MHz(이 드라이버는 400 kHz 이하 가정) |

## 설계 메모 (설계안)
- Basys3 3.3 V 로 구동하면 입력은 3.6 V 까지만 허용이라, ±4.096 V·±6.144 V 범위로 잡아도 입력은 3.3 V 근처가 한계입니다. 단일 종단 측정은 음수 코드가 나오지 않으며 실질 분해능은 15비트입니다.
- 단발 변환은 1 ms 간격으로 최대 200회(200 ms) 폴링합니다. 8 SPS 의 125 ms 보다 길게 잡았습니다(상한은 설계안).
- 비교기·ALERT/RDY 는 COMP_QUE=11 로 비활성화합니다(리셋 기본값과 같음). 사용하려면 GPIO 인터럽트 설계가 필요합니다.
- `ads1115_raw_to_uv` 는 raw×FSR/32768 을 0 쪽으로 내림합니다(187.5 µV → 187).

## 시험과 한계
- I2C 층을 데이터시트 규칙으로 만든 모델로 바꿔 검사: 주소 범위·NACK, Config 레지스터 왕복, 0xC283 비트 배치, 단발 폴링, 시간 초과, mux 8 × PGA 6 × DR 8 = 384 조합에서 필드 위치, LSB 표와의 일치. ASan/UBSan 통과. 바이트 순서·필드 위치·OS 판정을 일부러 틀리게 한 사본은 모두 실패로 잡힘.
- 모델은 내가 읽은 문서대로 내가 만든 것이라 문서 해석이 틀리면 같이 틀립니다. 보드에서 실행하지 않았습니다.
- 미확인·미작성: 일반 호출 리셋, 고속 모드 절차, 임계값 레지스터 사용, 실제 변환 지연(1/DR 이외의 시작 지연).
