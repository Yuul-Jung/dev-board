# ILI9341 전용 RTL (설계안, 시뮬레이션·합성 전)

<!-- nav -->[저장소 홈](../../../README.md) › [devices](../../README.md) › [spi](../README.md)

AXI Quad SPI 로는 D/CX 선과 화면 채우기를 CPU 없이 처리할 수 없어서 만든 작은 전용 엔진입니다.
구조: `ili9341_axil_top.v`(배선만) + `ili9341_axil_regs.v`(AXI4-Lite) + `ili9341_engine.v`(SPI 모드 0, MSB 먼저).

| 오프셋 | 이름 | 내용 |
|---|---|---|
| 0x00 | CTRL | [0] RESX 레벨(1=해제), [1] CSX 활성(1이면 Low), [2] 백라이트 |
| 0x04 | DIV | SCL = clk / (2×(DIV+1)), 리셋 기본 49 (100 MHz 가정 시 1 MHz) |
| 0x08 | TX(쓰기) / STATUS(읽기) | 쓰기 [7:0] 바이트, [8] D/CX. 읽기 [0] busy, [1] OVERRUN(읽으면 지워짐) |
| 0x0C | FILLCOLOR | RGB565 16비트 |
| 0x10 | FILLCNT | 쓰면 같은 색을 N픽셀(최대 2^20-1) 연속 송신 |

**의도적으로 넣지 않은 것**: 초기화 명령 순서, 리셋 Low 폭, 리셋 후/Sleep Out 후 대기 시간, SCL 최소 주기.
이번에 열어본 데이터시트 발췌에 해당 값이 없었습니다(목차만 있고 본문 없음). 소프트웨어가 정하도록 열어 두었고, DIV 기본값도 보수적인 값일 뿐 확인된 한계가 아닙니다.
모드 0 은 사용자 노션 문서 기준이며 데이터시트로 재확인하지 않았습니다.

시뮬레이션 불가 환경이라 `tb/tb_ili9341_engine.v`(명령 1바이트와 3픽셀 fill 확인)도 실행하지 못했습니다.

## 드라이버 (sw/ili9341.h/.c, 호스트 모의 테스트만)
- 이전 스케치(`sw/ili9341.c`)를 대체. 레지스터 맵은 위 표 그대로.
- **초기화 내용은 코드에 넣지 않음.** 호출자가 데이터시트 값으로 채운 표(`lcd_step_t`: 명령, 파라미터, 이후 대기 ms)를 `lcd_run_table` 로 실행하고, 리셋 Low 폭과 리셋 후 대기도 `lcd_hw_reset(low_ms, after_ms)` 인자로 받는다. 드라이버가 정한 숫자는 없다.
- 제공: `lcd_set_window`(2Ah → 2Bh → 2Ch, 범위 검사 240x320), `lcd_fill_rect`(FILLCNT 상한 2^20-1 초과 시 분할; 전체 화면 76,800 픽셀은 1회), `lcd_push_pixels`(상위 바이트 먼저, 16비트 색 가정), busy 대기 타임아웃과 OVERRUN 보고.
- 테스트(`tb/test_ili9341_sw.c`): 윈도우 바이트열, 전체 화면 fill 개수·색, 표 실행·대기 호출, 리셋 대기 시 RESX 레벨, 오류 경로 → ALL PASS. 모의 레지스터는 내가 쓴 RTL 의 사양을 흉내낸 것이라 RTL 자체의 검증이 아님.
- 막혀 있는 것: ILI9341 데이터시트 본문(표 19.3.4 타이밍, 8.2절 명령 파라미터, 12절 전원 시퀀스, 15.4 리셋 타이밍)을 열 수 있는 사본을 구하지 못했다(열린 사본은 목차와 일부 페이지뿐). 표에 채울 COLMOD·MADCTL 값, 대기 시간, DIV 한계가 모두 이 문서에 달려 있다 — 데이터시트 PDF 를 받으면 초기화 표를 만든다.
